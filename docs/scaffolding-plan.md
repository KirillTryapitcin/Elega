# Repository scaffolding plan (M0)

Status: Step 2 blueprint draft. Nothing below exists yet; M0 creates it.

## Layout

```
elega/
├─ apps/
│  ├─ web/          Next.js App Router PWA (includes /admin routes, see note)
│  ├─ api/          NestJS + Fastify: REST /api/v1 + Socket.IO gateway
│  │  └─ src/modules/{auth,users,relationships,posts,feed,stories,media,chat,
│  │                  notifications,groups,events,search,moderation,admin,platform}/
│  │       each: controller, service, repository, policy, dto, events, *.spec.ts
│  └─ worker/       BullMQ consumers; imports api modules' services, not controllers
├─ packages/
│  ├─ shared/       Zod schemas, types, constants, policy matrix, realtime events
│  ├─ api-client/   Generated from OpenAPI (openapi-typescript + openapi-fetch)
│  ├─ ui/           Design system (Radix / shadcn-based), Storybook
│  ├─ config/       ESLint, tsconfig, Tailwind presets, design tokens
│  └─ i18n/         ru and en ICU catalogs
├─ infra/
│  ├─ docker/       Dockerfiles (multi-stage, non-root), compose overrides
│  ├─ caddy/        Reverse proxy config
│  ├─ grafana/      Dashboards as JSON
│  └─ scripts/      backup, restore, seed, reset-db
├─ docs/            this blueprint + runbooks, legal templates, progress log
├─ tests/
│  ├─ e2e/          Playwright
│  └─ load/         k6
├─ .github/workflows/
├─ docker-compose.yml
├─ .env.example
├─ README.md, CONTRIBUTING.md, SECURITY.md, ROADMAP.md, CHANGELOG.md
```

Admin note: the brief allows `apps/admin` or `/admin` inside web. Proposal: `/admin` routes
in `apps/web` behind a separate layout, role check and 2FA, so the design system and auth
are shared; the API side stays isolated under `/api/v1/admin/*`. A separate app can be split
out later if the admin needs its own deploy or IP restriction at the edge.

## Tooling

| Concern | Choice |
| --- | --- |
| Package manager | pnpm workspaces, exact versions, `pnpm-lock.yaml` committed |
| Orchestrator | Turborepo (cached `build`, `lint`, `typecheck`, `test`) |
| Runtime | Node.js 22 LTS (`.nvmrc`, `engines`) |
| TypeScript | `strict`, `noUncheckedIndexedAccess`, project references |
| Lint / format | ESLint flat config with typescript-eslint, `eslint-plugin-security`, `eslint-plugin-boundaries`; Prettier |
| Git hooks | Husky + lint-staged + commitlint (Conventional Commits) |
| Tests | Vitest (unit), Vitest + Testcontainers + Supertest (integration), Playwright (e2e), axe-core, k6 |
| API docs | OpenAPI generated by `@nestjs/swagger` from Zod DTOs (`nestjs-zod`); Swagger UI only outside production |
| Dependencies | Renovate, `pnpm audit`, license check |

Library versions are chosen at M0 from current stable releases after reading release notes,
and pinned exactly (brief §4.5). None are guessed in this plan.

## Scripts (root `package.json`)

| Script | Does |
| --- | --- |
| `pnpm dev` | Compose services (postgres, redis, minio, mailpit) + all apps with hot reload |
| `pnpm build` / `lint` / `typecheck` / `test` | Turborepo pipelines |
| `pnpm db:migrate` / `db:reset` / `seed` | Migrations; reset; deterministic Russian demo data (refuses to run when `NODE_ENV=production`) |
| `pnpm api:generate` | Regenerate OpenAPI spec and `packages/api-client` |
| `pnpm test:e2e` / `test:load` | Playwright / k6 |

## Local stack (`docker compose up --build`)

postgres 16, redis 7, minio (+ bucket init), mailpit, api, worker, web, caddy; optional
profile `observability`: prometheus, grafana, loki, otel-collector, glitchtip.

## CI (GitHub Actions)

1. Install with pnpm cache.
2. Lint, typecheck, commitlint on PR title.
3. Unit tests with coverage (business logic ≥ 80 %, policies 100 %).
4. Integration tests against Postgres and Redis service containers.
5. Migration test: apply all migrations to an empty DB and roll back the last.
6. Build all apps; bundle budget (initial route ≤ 170 KB gzip).
7. OpenAPI diff check; generated client must be in sync.
8. E2E smoke (full suite nightly), axe checks.
9. Security: `pnpm audit`, gitleaks, Trivy on images, CodeQL.
10. On `main`: build and push images tagged with SHA; deploy to staging; production deploy
    by manual approval (from M11a).

## M0 exit criteria (from the plan)

From a clean clone, `docker compose up --build` starts everything; `/healthz` and `/readyz`
are green; CI is green on an empty feature; the API client is generated from the spec;
design tokens and a base UI kit render in Storybook in light and dark themes; ru/en i18n
skeleton with plural rules is in place.
